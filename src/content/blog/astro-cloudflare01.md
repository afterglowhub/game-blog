# 「ブログの維持費、毎月固定で支払い続けるのは、運用コストとして最適と言えるでしょうか？」

そう考え、「費用ゼロ・表示速度の最大化」を実現するブログ環境を構築してみました。正直なところ、この圧倒的な快適さを知ってしまうと、もうWordPressには戻れません。

---

# 結論：運用して分かった「Astro」3つの納得ポイント

## 1. 固定費を「年間ドメイン代」のみへ最小化

これまでのWordPress運用では、レンタルサーバー代として年間1万円近いコストがかかるのが一般的でした。

しかし、AstroとCloudflare Pagesを組み合わせれば、サーバー費用は永年無料。必要なのは純粋なドメイン更新料（年1,000円程度）のみとなり、年間で約8,600円のコストダウンを無理なく実現できます。

## 2. 読者を待たせない「異次元の表示速度」

サイトの読み込み速度は、SEO（検索評価）と読者満足度に直結します。

| 環境 | 表示速度 | 読者の体感 |
|:---|:---|:---|
| WordPress | 1.5〜3.0秒 | 少し間（ま）があるな |
| Astro | 0.1〜0.3秒 | クリックした瞬間に表示される |

この「一瞬で表示される快感」は、静的サイトジェネレーターであるAstroならではの強みです。

## 3. セキュリティ管理からの解放

WordPressにつきものの「プラグイン更新」や「セキュリティ対策」の悩みから解放されます。管理画面が存在しない仕組みのため、不正アクセスのリスクを構造的に排除。長期運用において、この「安心感」は代えがたいメリットです。

# 実際の構築手順：本当に60分でできた

## 準備編：アカウント作成（10分）

必要なツールは以下の3つだけ。すべて無料で使えます。

1. GitHub：コードを保存する場所
2. Cloudflare Pages：サイトを世界に公開する場所
3. VS Code：記事を書くためのエディタ

Node.jsのインストール（Ubuntu例）：

```bash
sudo apt update
sudo apt install nodejs npm

# バージョン確認（v18以上ならOK）
node --version
```

## 実践編①：Astroサイト作成（15分）

Astroには魅力的なデザインテンプレートが数多く公開されていますが、まずは公式の「Blogテンプレート（blog）」で進めてみるのがおすすめです。

というのも、多機能なテンプレート（Astropaperなど）は設定が細かく、初心者のうちはフォントの変更や記事の追加だけでも、思わぬところでつまずきやすいからです。

筆者の経験：実は最初、高機能な「Astropaper」に挑戦したのですが、設定に手間取り、2本目の記事がどうしてもアップできない壁にぶつかりました。結局、このシンプルな構成に切り替えたことで、ようやく本来の目的である「執筆」に集中できるようになりました。

「黒い画面」が怖い人も大丈夫。以下を順番にコピペするだけで魔法のように完成します。

```bash
# 作業フォルダの作成
cd ~/Documents/Work
mkdir my-blog
cd my-blog

# この1行でブログの骨格が完成！
npm create astro@latest . --template blog --no-git --yes

# 依存ファイルのインストールと起動
npm install
npm run dev
```

ブラウザで `http://localhost:4321` を開くと、すでに美しいブログが表示されているはずです。

## 実践編②：GitHubに保存（15分）

ここが最初の山場です。慎重に進めましょう。

### 1. GitHubでリポジトリ作成

- GitHubにログインし「New repository」をクリック
- 名前を `my-blog` にし、Public を選択
- 重要：「Initialize this repository...」のチェックはすべて外す

### 2. ローカルと接続

```bash
git init
git add .
git commit -m "First commit"
git branch -M main
git remote add origin https://github.com/あなたのユーザー名/my-blog.git
git push -u origin main
```

### 認証エラーが出た場合の解決策

もし `git push` でエラーが出たら、以下のどちらかで解決できます。

VS Codeを使っている場合（推奨）：

1. 画面左下の「人型アイコン」をクリック
2. 「Sign in with GitHub」を選択してブラウザで認証
3. これだけで次回から自動ログインされます

ターミナルだけで完結させたい場合：

1. GitHubの Settings → Developer settings から Personal Access Token (classic) を発行
2. `git push` 時に求められるパスワード欄に、発行されたトークンを貼り付け

## 実践編③：Cloudflare Pagesで世界に公開（20分）

ここが一番ワクワクする、世界とつながる瞬間です。

### 1. プロジェクトの作成

- Cloudflare Pagesにログインし、「Create a project」をクリック
- 「Connect to Git」→「GitHub」を選択
- 先ほど作成した `my-blog` リポジトリを選択して連携します

### 2. ビルド設定（ここが最重要！）

以下の表の通りに設定してください。ここを間違えるとエラーになります。

| 項目 | 設定値 |
|:---|:---|
| Framework preset | Astro（自動検出されます） |
| Build command | npm run build |
| Build output directory | dist |

### 3. 環境変数の追加（忘れがちポイント）

Astroのビルドを安定させるために、以下の設定を必ず追加してください。

- Variable name: `NODE_VERSION`
- Value: `20`

### 4. デプロイ実行

最後に「Save and Deploy」をクリック！1〜3分ほど待って、「デプロイ成功！」と表示されれば完了です。発行されたURLにアクセスしてみましょう。

# つまずいたポイントと解決法（実体験）

最初は誰でもつまずきます。私が実際に遭遇したエラーと解決策をまとめました。

原因1：フォルダ名に日本語が入っていた
- 症状：`npm create` やビルド時にエラーが出る
- 対策：フォルダ名を「ブログ」ではなく `my-blog` のように半角英数字にする

原因2：記事設定（Frontmatter）の引用符ミス
- 症状：記事が読み込まれない、または表示が崩れる
- 対策：タイトルなどは `' '`（シングルクォート）で囲むように統一する

原因3：画像パスのエラー
- 症状：ビルドが途中で止まる
- 対策：指定した画像ファイルが実際に存在するか確認。慣れるまでは画像なしのシンプル構成が確実です

# 記事を書く日常：これが最高に楽！

セットアップさえ終われば、あとは記事を書いてプッシュするだけ。このリズムが最高です。

1. 新しい記事ファイルを作成

```bash
# VS Codeで新しいmdファイルを開く
code src/content/blog/new-post.md
```

2. Markdownで執筆し、保存

3. コマンドを3つ打って公開！

```bash
git add .
git commit -m "新記事を追加"
git push origin main
```

これだけで、Cloudflareが自動でビルドを開始。1〜3分後には世界中に反映されます。管理画面にログインする手間すらありません。

## 結局、どちらを選ぶべき？

「技術的なことは避けたい、すぐに書き始めたい」という方は WordPress がおすすめです。

「固定費を削りたい、爆速にしたい、技術も学びたい」という方は Astro を選びましょう。

私は後者の「自力で最適化する道」を選びましたが、結果は大正解でした。無駄な固定費を削ぎ落としながら、最新の技術に触れる楽しさは格別です。

コマンドひとつで、自分のメディアが瞬時にアップデートされる。その「確かな手応え」と「コントロールしている実感」を、ぜひ一度体験してみてください。
